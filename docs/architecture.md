# Architecture

## Source and installation

`skills/doc-sync/` is the only editable source. `scripts/install.py` copies it into a host's skills directory (`--host <host>` or any `--target`) and verifies byte-for-byte parity. See [Host compatibility](host-compatibility.md) for supported `--host` presets and default targets.

```text
skills/doc-sync/  ->  scripts/install.py [--host HOST | --target DIR]  ->  <host>/skills/doc-sync/
   canonical                                                                installed mirror
```

- **Work root.** Hosts load every directory containing `SKILL.md` under a skills root, so staging and the rollback backup never live there. A standard `<base>/skills/doc-sync` target uses `<base>/.doc-sync-install/`. A shallow target, or one inside a repository (any ancestor holds `.git`), uses the user cache, `~/.cache/doc-sync-install/<hash>/` (`$XDG_CACHE_HOME` when set, `%LOCALAPPDATA%` on Windows), so no project tree gains install artifacts.
- **Replacement.** On one device the old target is renamed to the backup and the staged tree renamed into place. When the work root is on another device (`EXDEV`), the old target is first copied to the backup with symlinks preserved, and a marker is set before the new target is written. If anything fails after that marker, the partial target is removed, then the backup is restored if a target existed before, or the target is left absent.
- **Read-only modes.** `--check` and `--dry-run` write nothing, including bytecode for the loaded validator. `--check` fails on missing, extra, or content-divergent files.
- A divergent installation is replaced only with `--force`. Symlinked targets are refused. A symlink inside an existing target is reported as a difference rather than an error, so `--force` can move it into the backup unchanged and install a clean tree; the installed tree itself must contain no symlinks. Target paths are normalized with `os.path.abspath`, which folds `..` without following a symlinked final component.

## Documentation model

The skill keeps one layer of authoritative living docs; there is no parallel knowledge bundle. Each fact has one home, and docs record what the code cannot show: reasons, constraints, traps, and status in five states (`active`, `fallback`, `pending verification`, `historical`, `retired`).

A project's instruction entrypoint carries read-time routes (which contract to read before which kind of change, and when reading can stop) and one conditional write-time rule. This repository's [AGENTS.md](../AGENTS.md) is the reference example. The [maintenance standard](../skills/doc-sync/references/doc-maintenance.md) holds the cited rules.

## Validation

`skills/doc-sync/scripts/validate_docs.py` is shipped with the skill and uses only the Python 3.10+ standard library.

- **Two masking layers.** Block masking blanks frontmatter, fenced code (up to three leading spaces), indented code blocks, and HTML comments, but keeps 4-space nested list items and inline code text. Heading anchors and backtick paths are read from this layer, so a heading such as ``## Using `foo()` `` keeps its code text in the anchor. Full masking also blanks inline code spans, including spans that cross lines within a paragraph, and is the only layer used to extract Markdown links. A leading `---` counts as frontmatter only when a later line is exactly `---`, the first enclosed line is not blank, and every enclosed non-blank, non-comment line is indented or looks like a YAML key or list item; a leading thematic break stays Markdown.
- **Discovery and history.** Living Markdown excludes hidden, build, artifact, vendor, and `templates/` directories. Relative links in generator templates may resolve from their rendered destinations. Explicit links from living docs into excluded directories still resolve against disk. Files beneath a directory named `history`, `historical`, `archive`, `archived`, or `superpowers` are historical regardless of case. Additional directories come from `--historical-dir` and entrypoint comments such as `<!-- doc-sync: historical-dir custom/logs -->`. The comment also accepts `historical-dirs`, an optional equals sign, and a comma- or whitespace-separated list. The checker normalizes separators and ignores absolute or escaping directories. Declaration scanning masks fenced, indented, and inline code while preserving HTML comments. Historical files are exempt from stale link, anchor, backtick path, and reachability diagnostics. Public path restrictions still apply.
- **Reachability.** Traversal starts at root `AGENTS.md` and `CLAUDE.md`, with `README.md` as the fallback when neither exists. It follows Markdown links to project documents. Reached entrypoint and index files (`AGENTS.md`, `CLAUDE.md`, `README.md`, any `index.md`) also follow `@path` imports and backtick paths to project Markdown. Unreachable living Markdown under `docs/` is a warning by default and an error with `--strict`. A root `CLAUDE.md` beside `AGENTS.md` without an `@AGENTS.md` import is a warning.
- **Links and anchors.** A line such as `[label]: target` is a reference definition only when the target is followed by nothing or a single-line title (the target may also sit alone on the next line). A blank line ends a link's bracket text. Relative links resolve from the document's directory, and a leading `/` resolves from the project root. Recognized home paths resolve as filesystem absolute paths. In default mode, relative links and imports may cross the project boundary, including through symlinks. The checker verifies existence, letter case below the common ancestor or matched home directory where feasible, and heading or HTML anchors for Markdown fragments. External targets stay outside the reachability graph.
- **Backtick paths.** Git repositories derive top-level directory names from tracked files. Other projects use their directory listing. Each document also recognizes directory names listed directly under its directory and each ancestor below the project root. These listings are cached and use the same directory exclusions as discovery. Paths starting with a recognized directory name are tried from the document directory through its ancestors up to the project root. Paths starting with `./` or `../` try the document directory and then the project root. The checker skips artifact, template, and vendor path segments, obvious placeholders, globs, and text with spaces. It queries Git once for missing paths eligible for ignore checks, excluding prefixes that cross symlinks or nested repositories. An ignored attempt suppresses the diagnostic for that candidate. Unresolved paths produce warnings even with `--strict`.
- **Private paths.** `--check-private-paths` rejects links and imports that leave the root lexically or through a symlink, and makes outside-root bases ineligible for backtick path resolution. It scans files listed by `git ls-files -z --cached --others --exclude-standard` for POSIX and Windows home paths, including files excluded from living Markdown. Without Git enumeration, it scans the filtered directory walk.
- **Skill metadata.** `validate_skill_tree()` checks `SKILL.md` frontmatter, size limits, local links, and optional `agents/openai.yaml`. Its minimal YAML reader accepts only block mappings of scalars, and every error names the offending field. `install.py` and `validate_repo.py` both call it.

`scripts/validate_repo.py` checks the required files, skill metadata, and the absence of `CLAUDE.md`. It runs documentation validation with strict reachability and private-path rejection, and fails on any warning or error. It also checks that every Python file parses as Python 3.10 (`ast.parse(..., feature_version=(3, 10))`), imports only modules in `sys.stdlib_module_names`, and passes worktree and staged whitespace checks. The test suite covers the validator, installer recovery and isolation, and the repository gate.

## Evidence boundaries

The checks read local files only. A pass establishes structure and navigation, not that a documented fact is true, current, reviewed, or deployed. They do not measure whether a model finds hidden constraints or skips unneeded reading; that needs forward tests (see [Maintenance](maintenance.md#forward-testing)).
